## О чём эта работа

На заводе АО «ПМЗ» станки иногда ломаются. Пока станок сломан, он не работает — это называется **простой**. Чем больше простой, тем меньше завод успевает сделать.

Всё, что происходит со станками за смену, записывается в **журнал** — обычный текстовый файл. Например:

```
2027-01-20 08:05;EQ-001;ОТКАЗ
2027-01-20 09:10;EQ-001;ПОЧИНЕН
```

Это значит: станок EQ-001 сломался в 08:05, а в 09:10 его починили. Значит, он простоял 1 час 5 минут.

Сейчас начальник ремонтной службы каждое утро считает простои по такому журналу **вручную**. Это долго, и легко ошибиться.

**Вы напишете программу, которая сделает это за него.** Она:

- прочитает журнал;
- посчитает, сколько простоял каждый станок;
- найдёт самый проблемный станок;
- отбросит строки с ошибками и скажет, что с ними не так;
- заметит подозрительные записи;
- сохранит готовый отчёт в файл и таблицу для Excel.

Это и есть **автоматизация**: программа берёт на себя скучную повторяющуюся работу человека.

## Часть 1. Новое: словарь Dictionary

### Зачем нужен словарь

Вы уже знаете массив. В массиве значение достаётся **по номеру** ячейки: `grades[0]`, `grades[1]`, `grades[2]`.

Но на заводе станки называют не номерами 0, 1, 2, а **кодами**: EQ-001, EQ-007, EQ-012. Хочется спросить программу: «сколько раз ломался станок EQ-007?», а не «что лежит в ячейке номер 6?».

Для этого и нужен **словарь**. В нём значение достаётся **по ключу**.

Представьте телефонную книгу. Вы ищете человека **по имени** и находите его **номер**. Имя — это ключ, номер — значение. Словарь в C# работает так же.

| | Массив | Словарь |
| --- | --- | --- |
| Ищем по | номеру: 0, 1, 2 | ключу: "EQ-001", "EQ-007" |
| Как достать | `grades[0]` | `failures["EQ-001"]` |
| Размер | задаётся сразу и не меняется | растёт сам, как List |

### Как создать словарь

```csharp
Dictionary<string, int> failures = new Dictionary<string, int>();
```

В угловых скобках `< >` **два** типа через запятую:

- первый — **тип ключа**. Здесь `string`: ключом будет код станка, это текст;
- второй — **тип значения**. Здесь `int`: значением будет число отказов.

Читается так: «словарь, где по тексту хранится целое число».

### Что можно делать со словарём

Замените всё содержимое `Program.cs` этим примером и запустите. В новом проекте код можно писать прямо в файле, без класса и метода `Main`, — для небольших примеров это удобно:

```csharp
Dictionary<string, int> failures = new Dictionary<string, int>();

// Записать значение по ключу
failures["EQ-001"] = 2;
failures["EQ-003"] = 1;

// Прочитать значение по ключу
Console.WriteLine(failures["EQ-001"]);

// Если ключ уже есть — старое значение заменится новым
failures["EQ-001"] = 5;
Console.WriteLine(failures["EQ-001"]);

// Сколько всего ключей в словаре
Console.WriteLine(failures.Count);

// Есть ли такой ключ
Console.WriteLine(failures.ContainsKey("EQ-001"));
Console.WriteLine(failures.ContainsKey("EQ-007"));

// Удалить ключ вместе с его значением
failures.Remove("EQ-003");
Console.WriteLine(failures.Count);
```

<details>
<summary>▶ Что должно получиться</summary>

```
2
5
2
True
False
1
```

</details>

Разберём, что тут важно:

- **Ключи не повторяются.** Когда мы второй раз записали `failures["EQ-001"] = 5`, двух значений не появилось — старое (2) заменилось новым (5).
- `ContainsKey` отвечает `True` (да) или `False` (нет): есть ли в словаре такой ключ.
- `Count` — сколько ключей в словаре сейчас.

> [!WARNING]
> **Главная ловушка словаря.** Если прочитать ключ, которого нет, программа **упадёт** с ошибкой `KeyNotFoundException`.
>
> Попробуйте: допишите в конец примера `Console.WriteLine(failures["EQ-007"]);` и запустите. Программа упадёт, потому что ключа EQ-007 в словаре нет.
>
> Поэтому перед чтением всегда проверяют, есть ли ключ.

### Безопасное чтение: TryGetValue

Помните `int.TryParse`? Он пытается превратить текст в число и **не падает**, если не получилось, а просто возвращает `false`.

У словаря есть такой же метод — `TryGetValue`. Он пытается достать значение и **не падает**, если ключа нет:

```csharp
if (failures.TryGetValue("EQ-007", out int count))
{
    Console.WriteLine($"EQ-007 ломался {count} раз");
}
else
{
    Console.WriteLine("Про EQ-007 данных нет");
}
```

Если ключ есть — метод вернёт `true` и положит значение в переменную `count`. Если нет — вернёт `false`, и программа пойдёт в `else`.

### Как перебрать весь словарь

`foreach` по словарю выдаёт **пары** «ключ — значение». У каждой пары два свойства: `Key` (ключ) и `Value` (значение).

```csharp
foreach (KeyValuePair<string, int> pair in failures)
{
    Console.WriteLine($"{pair.Key}: {pair.Value}");
}
```

`KeyValuePair<string, int>` — это и есть «пара ключ-значение». Типы в скобках те же, что у словаря.

> [!NOTE]
> У словаря **нет порядка**. В каком порядке `foreach` выдаст пары, заранее не известно. Если порядок важен — например, в отчёте, — ключи сортируют отдельно. Так сделано и в нашей программе.

### Разминка 1: посчитать отказы

Задача: есть список кодов станков, которые ломались за смену. Нужно посчитать, сколько раз сломался каждый.

```csharp
string[] events = { "EQ-001", "EQ-003", "EQ-001", "EQ-007", "EQ-001" };
Dictionary<string, int> count = new Dictionary<string, int>();

foreach (string code in events)
{
    if (count.ContainsKey(code))
    {
        // Станок уже встречался — прибавляем 1 к его числу
        count[code]++;
    }
    else
    {
        // Станок встретился впервые — заводим для него ключ
        count[code] = 1;
    }
}

foreach (KeyValuePair<string, int> pair in count)
{
    Console.WriteLine($"{pair.Key}: {pair.Value}");
}
```

<details>
<summary>▶ Что должно получиться</summary>

```
EQ-001: 3
EQ-003: 1
EQ-007: 1
```

</details>

Шаблон **«если ключ есть — прибавить, если нет — создать»** — самый частый приём со словарём. Запомните его: в основной программе он встретится дважды.

> [!TIP]
> Попробуйте убрать `if` и оставить только `count[code]++;`. Программа упадёт на первом же коде. Почему? Прибавлять единицу не к чему — ключа ещё нет.

## Часть 2. Новое: дата и время

### DateTime — момент времени

`DateTime` хранит **дату и время вместе**: «20 января 2027 года, 08:05».

Создать его можно, перечислив по порядку: год, месяц, день, часы, минуты, секунды.

```csharp
DateTime broken = new DateTime(2027, 1, 20, 8, 5, 0);
```

Вывести дату можно в нужном виде. Для этого в интерполяции после двоеточия пишут **формат**:

```csharp
Console.WriteLine($"{broken:HH:mm}");
Console.WriteLine($"{broken:dd.MM.yyyy}");
Console.WriteLine($"{broken:yyyy-MM-dd HH:mm}");
```

<details>
<summary>▶ Что должно получиться</summary>

```
08:05
20.01.2027
2027-01-20 08:05
```

</details>

Буквы формата:

| Буквы | Что это | Пример |
| --- | --- | --- |
| `yyyy` | год | 2027 |
| `MM` | месяц | 01 |
| `dd` | день | 20 |
| `HH` | часы (от 0 до 23) | 08 |
| `mm` | минуты | 05 |

> [!WARNING]
> **`MM` и `mm` — разные вещи!** Большие `MM` — это **месяц**, маленькие `mm` — **минуты**. Если написать `HH:MM`, вместо 08:05 получится 08:01, потому что январь — первый месяц. Это одна из самых частых ошибок.

### Из текста в DateTime

В журнале время записано **текстом**: `"2027-01-20 08:05"`. Чтобы с ним работать, текст нужно превратить в `DateTime`.

Для этого есть `DateTime.TryParseExact`. Он похож на `int.TryParse`, но ему нужно сказать, **в каком виде** записана дата.

```csharp
string text = "2027-01-20 08:05";

bool ok = DateTime.TryParseExact(
    text, "yyyy-MM-dd HH:mm", CultureInfo.InvariantCulture,
    DateTimeStyles.None, out DateTime time);

if (ok)
{
    Console.WriteLine($"Прочитано: {time:HH:mm}");
}
else
{
    Console.WriteLine("Неверная дата");
}
```

Чтобы этот пример заработал, в **самое начало** файла `Program.cs` добавьте строку:

```csharp
using System.Globalization;
```

Что передаём в метод, по порядку:

1. `text` — текст, который превращаем в дату;
2. `"yyyy-MM-dd HH:mm"` — в каком виде он записан;
3. `CultureInfo.InvariantCulture` — «не зависеть от языка компьютера»;
4. `DateTimeStyles.None` — «без особых настроек»;
5. `out DateTime time` — куда положить готовую дату.

> [!TIP]
> Пункты 3 и 4 пока можно просто переписывать — они всегда одинаковые. Главное — понимать пункты 1, 2 и 5.

Если текст не подходит под формат — например, `"2027-01-20 25:70"` (25 часов не бывает), — метод вернёт `false`, и программа **не упадёт**.

### TimeSpan — промежуток времени

Если `DateTime` — это показание **часов** («сейчас 08:05»), то `TimeSpan` — показание **секундомера** («прошло 1 час 5 минут»).

`TimeSpan` получается сам, когда **из одной даты вычитают другую**:

```csharp
DateTime broken = new DateTime(2027, 1, 20, 8, 5, 0);
DateTime repaired = new DateTime(2027, 1, 20, 9, 10, 0);

TimeSpan downtime = repaired - broken;

Console.WriteLine(downtime.Hours);
Console.WriteLine(downtime.Minutes);
Console.WriteLine(downtime.TotalMinutes);
Console.WriteLine(downtime.TotalHours);
```

<details>
<summary>▶ Что должно получиться</summary>

```
1
5
65
1,0833333333333333
```

На компьютере с английскими настройками в последней строке будет точка вместо запятой — это нормально.

</details>

У `TimeSpan` есть свойства **двух видов**. Их важно не путать:

| Свойство | Что значит | Для 1 ч 5 мин |
| --- | --- | --- |
| `Hours` | сколько целых часов | 1 |
| `Minutes` | сколько минут сверх часов | 5 |
| `TotalHours` | всё время в часах | 1,08 |
| `TotalMinutes` | всё время в минутах | 65 |

> [!WARNING]
> **Ловушка с `Hours`.** `Hours` считает часы только **в пределах одних суток**. Если станок простоял 26 часов 35 минут, `Hours` вернёт **2** — целые сутки он не считает. А `TotalHours` вернёт честные **26,58**. Поэтому для простоя в нашей программе используется `TotalHours`.

Промежутки можно **складывать**: `total += downtime`. Начинать сумму удобно с нулевого промежутка: `TimeSpan total = TimeSpan.Zero;`.

Даты и промежутки можно **сравнивать**: `time < lastTime`, `downtime > worstTime`.

## Часть 3. Пишем программу по шагам

Мы соберём программу за **шесть шагов**. После каждого шага программа запускается и что-то показывает. Так вы всегда будете видеть, что сделали.

### Как устроена программа

Программа состоит из двух частей.

**1. Память программы — поля вверху класса.** Это переменные, которые объявлены не внутри метода, а прямо в классе, над `Main`. Их видят **все** методы программы. В них программа копит то, что узнаёт из журнала: кто сломан, кто сколько простоял, какие строки битые.

### Шаг 1. Читаем журнал

Сначала просто научимся читать журнал и показывать его на экране. Замените **весь** код в `Program.cs` на этот:

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        string path = Path.Combine(AppContext.BaseDirectory, "events.log");
        string[] lines = ReadLog(path);

        if (lines.Length == 0)
        {
            Console.WriteLine("Нечего обрабатывать.");
            return;
        }

        for (int i = 0; i < lines.Length; i++)
        {
            Console.WriteLine($"{i + 1}: {lines[i]}");
        }
    }

    // Читает журнал. Если прочитать не вышло — сообщает и возвращает пустой массив.
    static string[] ReadLog(string path)
    {
        try
        {
            return File.ReadAllLines(path);
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Не удалось прочитать журнал: {ex.Message}");
            return Array.Empty<string>();
        }
    }
}
```

**Что здесь происходит:**

- `AppContext.BaseDirectory` — папка, откуда запущена программа. `Path.Combine` склеивает её с именем файла и получает полный путь к журналу.

### Шаг 2. Разбираем строку и отбрасываем битые

Теперь научим программу понимать каждую строку и откладывать в сторону строки с ошибками.

**1. Добавьте в самое начало файла** ещё две строки `using`:

**2. Добавьте в класс, над методом `Main`**, первые поля — память программы:

```csharp
// В каком виде записано время в журнале: год-месяц-день часы:минуты.

// Строки, которые не удалось прочитать.
```

**3. Добавьте два новых метода** (например, под методом `ReadLog`):

```csharp
// Разбирает одну строку журнала: проверяет её и учитывает событие.
static void ProcessLine(string line, int lineNumber)
{
    if (line.Trim() == "")
    {
        return;
    }

    string[] parts = line.Split(';');

    if (parts.Length != 3)
    {
        rejected.Add($"Строка {lineNumber}: должно быть 3 части, а их {parts.Length}");
        return;
    }

    string timeText = parts[0].Trim();
    string code = parts[1].Trim();
    string eventType = parts[2].Trim();

    bool isDate = DateTime.TryParseExact(
        timeText, DateFormat, CultureInfo.InvariantCulture,
        DateTimeStyles.None, out DateTime time);

    if (!isDate)
    {
        rejected.Add($"Строка {lineNumber}: неверная дата «{timeText}»");
        return;
    }

    if (!IsValidCode(code))
    {
        rejected.Add($"Строка {lineNumber}: неверный код станка «{code}»");
        return;
    }

    if (eventType != "ОТКАЗ" && eventType != "ПОЧИНЕН")
    {
        rejected.Add($"Строка {lineNumber}: неизвестное событие «{eventType}»");
        return;
    }

    // Сюда на следующих шагах добавим учёт поломок и ремонтов.
}

// Правильный код: ровно 6 символов, начинается с "EQ-", дальше число от 1 до 15.
static bool IsValidCode(string code)
{
    if (code.Length != 6 || !code.StartsWith("EQ-", StringComparison.Ordinal))
    {
        return false;
    }

    bool isNumber = int.TryParse(code.Substring(3), out int number);
    return isNumber && number >= 1 && number <= 15;
}
```

**4. В `Main` замените цикл** `for` на такой код:

```csharp
for (int i = 0; i < lines.Length; i++)
{
    ProcessLine(lines[i], i + 1);
}

Console.WriteLine($"Отброшено строк: {rejected.Count}");

foreach (string item in rejected)
{
    Console.WriteLine($"  {item}");
}
```

**Что здесь происходит:**

`ProcessLine` проверяет строку **по шагам**. На каждом шаге, если что-то не так, она записывает причину в список `rejected` и сразу выходит через `return`. До конца метода доходят только правильные строки.

1. **Пустая строка** — пропускаем молча, это не ошибка.
2. **`Split(';')`** режет строку по точке с запятой. Из `"2027-01-20 08:05;EQ-001;ОТКАЗ"` получается три части: `"2027-01-20 08:05"`, `"EQ-001"` и `"ОТКАЗ"`. Если частей не три — строка битая.
3. **`Trim()`** убирает случайные пробелы по краям каждой части.
4. **Дата** проверяется через `TryParseExact` — вы разбирали его в части 2.
5. **Код станка** проверяется методом `IsValidCode`.
6. **Событие** должно быть ровно `ОТКАЗ` или `ПОЧИНЕН`. Другие слова программа не знает.

**Как работает `IsValidCode`.** Правильный код — это ровно 6 символов, он начинается с `EQ-`, а дальше идёт число от 1 до 15, потому что на заводе 15 станков.

- `code.Length != 6` — длина не 6;
- `StartsWith("EQ-", StringComparison.Ordinal)` — начинается ли текст с `EQ-`. `Ordinal` значит «сравнивать строго, буква в букву»;
- `code.Substring(3)` — кусок текста, начиная с позиции 3. Из `"EQ-007"` получается `"007"`;
- `int.TryParse` превращает `"007"` в число 7, и мы проверяем, что оно от 1 до 15.

> [!NOTE]
> Почему `ПОЛОМКА` — ошибка, ведь по смыслу это то же, что `ОТКАЗ`? Программа не понимает смысл слов. Она сравнивает текст буква в букву. Поэтому в журнале все события должны быть записаны одинаково.

### Шаг 3. Считаем поломки и ремонты

Самое главное. Научим программу понимать, когда станок сломался, когда его починили, и сколько он простоял.

**Идея.** Заведём словарь «**кто сломан прямо сейчас**». Ключ — код станка, значение — время, когда он сломался.

- Пришла строка `ОТКАЗ` → кладём станок в этот словарь и запоминаем время.
- Пришла строка `ПОЧИНЕН` → достаём из словаря время поломки, считаем простой и убираем станок из словаря.

Например, EQ-001: в 08:05 `ОТКАЗ` — кладём в словарь со временем 08:05. В 09:10 `ПОЧИНЕН` — достаём 08:05, считаем 09:10 − 08:05 = 1:05 и убираем EQ-001 из словаря.

**1. Добавьте поля** (рядом с `rejected`):

```csharp
// Кто сломан прямо сейчас: код станка -> время, когда он сломался.
static Dictionary<string, DateTime> brokenNow = new Dictionary<string, DateTime>();

// Сколько всего простоял каждый станок за смену.
static Dictionary<string, TimeSpan> downtime = new Dictionary<string, TimeSpan>();

// Сколько раз ломался каждый станок.
static Dictionary<string, int> failureCount = new Dictionary<string, int>();

// Строки, которые прочитать удалось, но в них что-то подозрительное.
static List<string> warnings = new List<string>();
```

**2. Добавьте пять методов:**

```csharp
// Станок сломался: запоминаем, когда, и прибавляем к счётчику отказов.
static void RegisterFailure(string code, DateTime time, int lineNumber)
{
    if (brokenNow.ContainsKey(code))
    {
        warnings.Add($"Строка {lineNumber}: {code} снова сломался, хотя ещё не починен");
        return;
    }

    brokenNow[code] = time;

    if (failureCount.ContainsKey(code))
    {
        failureCount[code]++;
    }
    else
    {
        failureCount[code] = 1;
    }
}

// Станок починили: считаем, сколько он простоял, и убираем из сломанных.
static void RegisterRepair(string code, DateTime time, int lineNumber)
{
    if (!brokenNow.TryGetValue(code, out DateTime brokenAt))
    {
        warnings.Add($"Строка {lineNumber}: {code} починен, хотя не ломался");
        return;
    }

    if (time < brokenAt)
    {
        warnings.Add($"Строка {lineNumber}: {code} починен раньше, чем сломался");
        return;
    }

    AddDowntime(code, time - brokenAt);
    brokenNow.Remove(code);
}

// Прибавляет простой к сумме станка. Если станка ещё нет в словаре — заводит его.
static void AddDowntime(string code, TimeSpan duration)
{
    if (downtime.ContainsKey(code))
    {
        downtime[code] += duration;
    }
    else
    {
        downtime[code] = duration;
    }
}

// Простой в виде "часы:минуты". TotalHours, а не Hours: Hours обнуляется после суток.
static string FormatDuration(TimeSpan time)
{
    return $"{(int)time.TotalHours}:{time.Minutes:00}";
}

// У словаря нет порядка, поэтому коды станков сортируем перед выводом.
static List<string> GetSortedCodes()
{
    List<string> codes = new List<string>(downtime.Keys);
    codes.Sort();
    return codes;
}
```

**3. В методе `ProcessLine`** замените строку-комментарий `// Сюда на следующих шагах...` на этот код:

```csharp
if (eventType == "ОТКАЗ")
{
    RegisterFailure(code, time, lineNumber);
}
else
{
    RegisterRepair(code, time, lineNumber);
}
```

**4. В `Main`, после вывода отброшенных строк**, добавьте временный вывод результата:

```csharp
foreach (string code in GetSortedCodes())
{
    Console.WriteLine($"{code}: простой {FormatDuration(downtime[code])}, отказов {failureCount[code]}");
}

Console.WriteLine($"Предупреждения: {warnings.Count}");

foreach (string item in warnings)
{
    Console.WriteLine($"  {item}");
}
```

**Что здесь происходит:**

**`RegisterFailure` — станок сломался.**

- Если станок **уже** в словаре `brokenNow`, значит, он «сломался», ещё не будучи починенным. Так не бывает — это подозрительно, и программа пишет предупреждение.
- Иначе записываем время поломки: `brokenNow[code] = time`.
- И прибавляем 1 к числу отказов по знакомому шаблону из разминки 1: «если ключ есть — прибавить, если нет — создать».

**`RegisterRepair` — станок починили.**

- `TryGetValue` пытается достать время поломки. Если станка в словаре нет — его «починили», хотя он не ломался. Подозрительно — предупреждение.
- Если починили раньше, чем сломали, — тоже предупреждение.
- Иначе `time - brokenAt` даёт `TimeSpan` — сколько станок простоял. Прибавляем его к сумме и убираем станок из словаря: `brokenNow.Remove(code)`.

**`AddDowntime`** прибавляет простой к сумме станка по тому же шаблону «есть — прибавить, нет — создать».

**`FormatDuration`** превращает `TimeSpan` в текст вида `2:10`. Берёт `TotalHours`, а не `Hours` — из-за ловушки, которую вы видели в части 2.

**`GetSortedCodes`** делает из ключей словаря список и сортирует его методом `Sort()`. У словаря нет порядка, а нам нужно выводить станки по возрастанию кода.

### Шаг 4. Конец смены и подозрительное время

**Проблема 1.** EQ-005 сломался и не был починен до конца смены. Он простоял с 17:25 до 20:00, но программа этого не посчитала.

**Проблема 2.** В строке 12 время 13:30, а перед ней было 14:00. Время пошло **назад**. Журнал пишется по порядку, так быть не должно. Возможно, журнал исправляли вручную, задним числом.

**1. Добавьте поля:**

```csharp
// Смена 20 января 2027 года, с 08:00 до 20:00.
static readonly DateTime ShiftStart = new DateTime(2027, 1, 20, 8, 0, 0);
static readonly DateTime ShiftEnd = new DateTime(2027, 1, 20, 20, 0, 0);

// Станки, которые так и не починили до конца смены.
static List<string> stillBroken = new List<string>();

// Самое позднее время, которое уже встречалось в журнале.
static DateTime lastTime = DateTime.MinValue;
```

`static readonly` значит: значение задаётся один раз и больше не меняется. Начало и конец смены во время работы программы не меняются.

`DateTime.MinValue` — самая ранняя дата, какая бывает. Мы начинаем с неё, чтобы первое же время из журнала оказалось «позже».

**2. Добавьте метод:**

```csharp
// Кто остался сломанным к концу смены, простоял до самого конца.
static void CloseShift()
{
    foreach (KeyValuePair<string, DateTime> pair in brokenNow)
    {
        AddDowntime(pair.Key, ShiftEnd - pair.Value);
        stillBroken.Add(pair.Key);
    }

    brokenNow.Clear();
}
```

**3. В методе `ProcessLine`** перед строкой `if (eventType == "ОТКАЗ")` вставьте:

```csharp
// Журнал пишется по порядку, время не может идти назад.

{

else
{

}
```

**4. В `Main`** сразу после цикла `for` добавьте вызов:

**`CloseShift`** — конец смены. Все станки, которые остались в словаре `brokenNow`, так и простояли до конца смены. Для каждого считаем простой от времени поломки до 20:00 и запоминаем, что он до сих пор сломан. В конце словарь очищаем: `Clear()` удаляет все ключи.

**Проверка времени.** `lastTime` помнит самое позднее время, которое уже было. Если новое время **меньше** — время пошло назад, пишем предупреждение. Иначе запоминаем новое время как самое позднее.

### Шаг 5. Собираем красивый отчёт

Сейчас программа печатает результат кусками. Соберём настоящий отчёт.

**Что такое StringBuilder.** Отчёт — это много строк. Можно было бы складывать их так: `report = report + "новая строка"`. Но строки в C# **нельзя изменить**, поэтому каждое такое сложение создаёт **новую** строку и копирует в неё весь отчёт заново. Для длинного отчёта это медленно.

`StringBuilder` — это «черновик». В него можно дописывать сколько угодно строк через `AppendLine`, а в самом конце получить готовый текст одним вызовом `ToString()`.

**1. Добавьте в начало файла:**

```csharp
using System.Text;
```

**2. Добавьте два метода:**

```csharp
// Собирает текст отчёта.
static string BuildReport()
{
    StringBuilder report = new StringBuilder();

    report.AppendLine($"ОТЧЁТ ЗА СМЕНУ {ShiftStart:dd.MM.yyyy} ({ShiftStart:HH:mm}–{ShiftEnd:HH:mm})");
    report.AppendLine();
    report.AppendLine($"{"Станок",-11}{"Отказов",-10}Простой");

    TimeSpan total = TimeSpan.Zero;
    string worstCode = "";
    TimeSpan worstTime = TimeSpan.Zero;

    foreach (string code in GetSortedCodes())
    {
        TimeSpan time = downtime[code];
        int failures = failureCount[code];

        string mark = "";

        if (stillBroken.Contains(code))
        {
            mark = "  ДО СИХ ПОР СЛОМАН";
        }

        report.AppendLine($"{code,-11}{failures,-10}{FormatDuration(time)}{mark}");

        total += time;

        if (time > worstTime)
        {
            worstTime = time;
            worstCode = code;
        }
    }

    report.AppendLine();
    report.AppendLine($"Общий простой: {FormatDuration(total)}");

    if (worstCode != "")
    {
        report.AppendLine($"Хуже всех: {worstCode} ({FormatDuration(worstTime)})");
    }

    AppendList(report, "Отброшено строк", rejected);
    AppendList(report, "Предупреждения", warnings);

    return report.ToString();
}

// Дописывает в отчёт заголовок и список строк под ним.
static void AppendList(StringBuilder report, string title, List<string> items)
{
    report.AppendLine();
    report.AppendLine($"{title}: {items.Count}");

    foreach (string item in items)
    {
        report.AppendLine($"  {item}");
    }
}
```

**3. В `Main` удалите** весь временный вывод — вывод отброшенных строк, простоев и предупреждений — и вместо него, после `CloseShift();`, напишите:

```csharp

Console.WriteLine(report);
```

**Что здесь происходит:**

- `report.AppendLine(...)` дописывает строку в черновик. `AppendLine()` без текста — пустая строка для отступа.
- `{"Станок",-11}` — выравнивание: занять 11 позиций и прижать текст влево. Так колонки отчёта встают ровно.
- Пока перебираем станки, считаем **общий простой** (`total += time`) и ищем **худший станок** — с самым большим простоем. Это обычный поиск максимума: если текущий простой больше лучшего найденного, запоминаем этот станок.
- `stillBroken.Contains(code)` — есть ли станок в списке «до сих пор сломан». Если есть, рядом пишем пометку.
- `AppendList` дописывает заголовок и список под ним. Он нужен, чтобы не писать один и тот же код дважды — для отброшенных строк и для предупреждений.

### Шаг 6. Сохраняем в файлы

Последний шаг — сохранить отчёт в файл, а ещё сделать **таблицу CSV**, которую можно открыть в Excel.

**Что такое CSV.** Это таблица, записанная обычным текстом. Первая строка — названия столбцов, дальше по строке на каждую запись. Значения разделены точкой с запятой. Excel умеет открывать такие файлы как таблицу.

**1. Добавьте два метода:**

```csharp
// Собирает таблицу CSV для Excel.
static string BuildCsv()
{
    StringBuilder csv = new StringBuilder();
    csv.AppendLine("станок;отказов;простой_часов");

    foreach (string code in GetSortedCodes())
    {
        // InvariantCulture: дробная часть всегда через точку (2.17), на любом компьютере.
        string hours = downtime[code].TotalHours.ToString("0.00", CultureInfo.InvariantCulture);
        csv.AppendLine($"{code};{failureCount[code]};{hours}");
    }

    return csv.ToString();
}

// Сохраняет отчёт и CSV в папку reports рядом с программой.
static void SaveReports(string report)
{
    string folder = Path.Combine(AppContext.BaseDirectory, "reports");
    string date = ShiftStart.ToString("yyyy-MM-dd");

    string reportPath = Path.Combine(folder, $"shift-report-{date}.txt");
    string csvPath = Path.Combine(folder, $"shift-summary-{date}.csv");

    try
    {
        Directory.CreateDirectory(folder);
        File.WriteAllText(reportPath, report);
        File.WriteAllText(csvPath, BuildCsv());

        Console.WriteLine($"Сохранено: {reportPath}");
        Console.WriteLine($"Сохранено: {csvPath}");
    }
    catch (UnauthorizedAccessException)
    {
        Console.WriteLine("Нет прав на запись в папку reports.");
    }
    catch (IOException ex)
    {
        Console.WriteLine($"Не удалось сохранить отчёт: {ex.Message}");
    }

```

**2. В `Main`, в самом конце**, добавьте:

```csharp
SaveReports(report);
```

**Что здесь происходит:**

- `Directory.CreateDirectory` создаёт папку `reports`. Если она уже есть — ничего не делает и не выдаёт ошибку.
- `File.WriteAllText` записывает текст в файл целиком.
- Имена файлов содержат дату смены: `shift-report-2027-01-20.txt`. Так отчёты за разные дни не затрут друг друга.
- Запись обёрнута в `try`. Ошибок может быть две: нет прав на запись (`UnauthorizedAccessException`) или другая проблема с файлом (`IOException`).

<summary>▶ Полный код программы — для сверки</summary>

```csharp
using System;
using System.Collections.Generic;
using System.Globalization;
using System.IO;
using System.Text;

class Program
{
    // ===== Настройки смены =====

    // Смена 20 января 2027 года, с 08:00 до 20:00.
    static readonly DateTime ShiftStart = new DateTime(2027, 1, 20, 8, 0, 0);
    static readonly DateTime ShiftEnd = new DateTime(2027, 1, 20, 20, 0, 0);

    // В каком виде записано время в журнале: год-месяц-день часы:минуты.
    const string DateFormat = "yyyy-MM-dd HH:mm";

    // ===== Данные, которые программа копит, читая журнал =====

    // Кто сломан прямо сейчас: код станка -> время, когда он сломался.
    static Dictionary<string, DateTime> brokenNow = new Dictionary<string, DateTime>();

    // Сколько всего простоял каждый станок за смену.
    static Dictionary<string, TimeSpan> downtime = new Dictionary<string, TimeSpan>();

    // Сколько раз ломался каждый станок.
    static Dictionary<string, int> failureCount = new Dictionary<string, int>();

    // Станки, которые так и не починили до конца смены.
    static List<string> stillBroken = new List<string>();

    // Строки, которые не удалось прочитать.
    static List<string> rejected = new List<string>();

    // Строки, которые прочитать удалось, но в них что-то подозрительное.
    static List<string> warnings = new List<string>();

    // Самое позднее время, которое уже встречалось в журнале.
    static DateTime lastTime = DateTime.MinValue;

    static void Main()
    {
        string path = Path.Combine(AppContext.BaseDirectory, "events.log");
        string[] lines = ReadLog(path);

        if (lines.Length == 0)
        {
            Console.WriteLine("Нечего обрабатывать.");
            return;
        }

        for (int i = 0; i < lines.Length; i++)
        {
            // i + 1, потому что люди считают строки с 1, а массив — с 0.
            ProcessLine(lines[i], i + 1);
        }

        CloseShift();

        string report = BuildReport();
        Console.WriteLine(report);

        SaveReports(report);
    }

    // Читает журнал. Если прочитать не вышло — сообщает и возвращает пустой массив.
    static string[] ReadLog(string path)
    {
        try
        {
            return File.ReadAllLines(path);
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Не удалось прочитать журнал: {ex.Message}");
            return Array.Empty<string>();
        }
    }

    // Разбирает одну строку журнала: проверяет её и учитывает событие.
    static void ProcessLine(string line, int lineNumber)
    {
        if (line.Trim() == "")
        {
            return;
        }

        string[] parts = line.Split(';');

        if (parts.Length != 3)
        {
            rejected.Add($"Строка {lineNumber}: должно быть 3 части, а их {parts.Length}");
            return;
        }

        string timeText = parts[0].Trim();
        string code = parts[1].Trim();
        string eventType = parts[2].Trim();

        bool isDate = DateTime.TryParseExact(
            timeText, DateFormat, CultureInfo.InvariantCulture,
            DateTimeStyles.None, out DateTime time);

        if (!isDate)
        {
            rejected.Add($"Строка {lineNumber}: неверная дата «{timeText}»");
            return;
        }

        if (!IsValidCode(code))
        {
            rejected.Add($"Строка {lineNumber}: неверный код станка «{code}»");
            return;
        }

        if (eventType != "ОТКАЗ" && eventType != "ПОЧИНЕН")
        {
            rejected.Add($"Строка {lineNumber}: неизвестное событие «{eventType}»");
            return;
        }

        // Журнал пишется по порядку, время не может идти назад.
        // Если пошло — возможно, журнал исправляли вручную. Предупреждаем, но строку учитываем.
        if (time < lastTime)
        {
            warnings.Add($"Строка {lineNumber}: время пошло назад ({time:HH:mm} после {lastTime:HH:mm})");
        }
        else
        {
            lastTime = time;
        }

        if (eventType == "ОТКАЗ")
        {
            RegisterFailure(code, time, lineNumber);
        }
        else
        {
            RegisterRepair(code, time, lineNumber);
        }
    }

    // Правильный код: ровно 6 символов, начинается с "EQ-", дальше число от 1 до 15.
    static bool IsValidCode(string code)
    {
        if (code.Length != 6 || !code.StartsWith("EQ-", StringComparison.Ordinal))
        {
            return false;
        }

        bool isNumber = int.TryParse(code.Substring(3), out int number);
        return isNumber && number >= 1 && number <= 15;
    }

    // Станок сломался: запоминаем, когда, и прибавляем к счётчику отказов.
    static void RegisterFailure(string code, DateTime time, int lineNumber)
    {
        if (brokenNow.ContainsKey(code))
        {
            warnings.Add($"Строка {lineNumber}: {code} снова сломался, хотя ещё не починен");
            return;
        }

        brokenNow[code] = time;

        if (failureCount.ContainsKey(code))
        {
            failureCount[code]++;
        }
        else
        {
            failureCount[code] = 1;
        }
    }

    // Станок починили: считаем, сколько он простоял, и убираем из сломанных.
    static void RegisterRepair(string code, DateTime time, int lineNumber)
    {
        if (!brokenNow.TryGetValue(code, out DateTime brokenAt))
        {
            warnings.Add($"Строка {lineNumber}: {code} починен, хотя не ломался");
            return;
        }

        if (time < brokenAt)
        {
            warnings.Add($"Строка {lineNumber}: {code} починен раньше, чем сломался");
            return;
        }

        AddDowntime(code, time - brokenAt);
        brokenNow.Remove(code);
    }

    // Прибавляет простой к сумме станка. Если станка ещё нет в словаре — заводит его.
    static void AddDowntime(string code, TimeSpan duration)
    {
        if (downtime.ContainsKey(code))
        {
            downtime[code] += duration;
        }
        else
        {
            downtime[code] = duration;
        }
    }

    // Кто остался сломанным к концу смены, простоял до самого конца.
    static void CloseShift()
    {
        foreach (KeyValuePair<string, DateTime> pair in brokenNow)
        {
            AddDowntime(pair.Key, ShiftEnd - pair.Value);
            stillBroken.Add(pair.Key);
        }

        brokenNow.Clear();
    }

    // Собирает текст отчёта.
    static string BuildReport()
    {
        StringBuilder report = new StringBuilder();

        report.AppendLine($"ОТЧЁТ ЗА СМЕНУ {ShiftStart:dd.MM.yyyy} ({ShiftStart:HH:mm}–{ShiftEnd:HH:mm})");
        report.AppendLine();
        report.AppendLine($"{"Станок",-11}{"Отказов",-10}Простой");

        TimeSpan total = TimeSpan.Zero;
        string worstCode = "";
        TimeSpan worstTime = TimeSpan.Zero;

        foreach (string code in GetSortedCodes())
        {
            TimeSpan time = downtime[code];
            int failures = failureCount[code];

            string mark = "";

            if (stillBroken.Contains(code))
            {
                mark = "  ДО СИХ ПОР СЛОМАН";
            }

            report.AppendLine($"{code,-11}{failures,-10}{FormatDuration(time)}{mark}");

            total += time;

            if (time > worstTime)
            {
                worstTime = time;
                worstCode = code;
            }
        }

        report.AppendLine();
        report.AppendLine($"Общий простой: {FormatDuration(total)}");

        if (worstCode != "")
        {
            report.AppendLine($"Хуже всех: {worstCode} ({FormatDuration(worstTime)})");
        }

        AppendList(report, "Отброшено строк", rejected);
        AppendList(report, "Предупреждения", warnings);

        return report.ToString();
    }

    // Собирает таблицу CSV для Excel.
    static string BuildCsv()
    {
        StringBuilder csv = new StringBuilder();
        csv.AppendLine("станок;отказов;простой_часов");

        foreach (string code in GetSortedCodes())
        {
            // InvariantCulture: дробная часть всегда через точку (2.17), на любом компьютере.
            string hours = downtime[code].TotalHours.ToString("0.00", CultureInfo.InvariantCulture);
            csv.AppendLine($"{code};{failureCount[code]};{hours}");
        }

        return csv.ToString();
    }

    // Сохраняет отчёт и CSV в папку reports рядом с программой.
    static void SaveReports(string report)
    {
        string folder = Path.Combine(AppContext.BaseDirectory, "reports");
        string date = ShiftStart.ToString("yyyy-MM-dd");

        string reportPath = Path.Combine(folder, $"shift-report-{date}.txt");
        string csvPath = Path.Combine(folder, $"shift-summary-{date}.csv");

        try
        {
            Directory.CreateDirectory(folder);
            File.WriteAllText(reportPath, report);
            File.WriteAllText(csvPath, BuildCsv());

            Console.WriteLine($"Сохранено: {reportPath}");
            Console.WriteLine($"Сохранено: {csvPath}");
        }
        catch (UnauthorizedAccessException)
        {
            Console.WriteLine("Нет прав на запись в папку reports.");
        }
        catch (IOException ex)
        {
            Console.WriteLine($"Не удалось сохранить отчёт: {ex.Message}");
        }
    }

    // У словаря нет порядка, поэтому коды станков сортируем перед выводом.
    static List<string> GetSortedCodes()
    {
        List<string> codes = new List<string>(downtime.Keys);
        codes.Sort();
        return codes;
    }

    // Простой в виде "часы:минуты". TotalHours, а не Hours: Hours обнуляется после суток.
    static string FormatDuration(TimeSpan time)
    {
        return $"{(int)time.TotalHours}:{time.Minutes:00}";
    }

    // Дописывает в отчёт заголовок и список строк под ним.
    static void AppendList(StringBuilder report, string title, List<string> items)
    {
        report.AppendLine();
        report.AppendLine($"{title}: {items.Count}");

        foreach (string item in items)
        {
            report.AppendLine($"  {item}");
        }
    }
}
```

## Эксперименты

Каждый эксперимент — это одна изменённая строка, после которой программа начинает **тихо врать**. Не падает, а выдаёт неправильный результат. Это самые опасные ошибки. После каждого эксперимента верните код как был.

**Эксперимент 1. Пропавшие сутки.** В поле `ShiftEnd` поменяйте день на следующий: `new DateTime(2027, 1, 21, 20, 0, 0)`. EQ-005 теперь простоял 26 часов 35 минут, отчёт покажет `26:35`. Затем в `FormatDuration` замените `time.TotalHours` на `time.Hours`. Что стало с простоем EQ-005?

<details>
<summary>▶ Ответ</summary>

Вместо `26:35` получится `2:35`. Целые сутки молча пропали, потому что `Hours` считает часы только в пределах суток.

</details>

**Эксперимент 2. Забытый Remove.** В методе `RegisterRepair` закомментируйте строку `brokenNow.Remove(code);` (поставьте перед ней `//`). Посмотрите на отчёт.

<details>
<summary>▶ Ответ</summary>

Починенные станки остаются в словаре «сломан прямо сейчас». Поэтому второй отказ EQ-001 программа считает подозрительным, а в конце смены все станки получают лишний простой до 20:00 и пометку «до сих пор сломан». Одна пропущенная строка — и весь отчёт неверный.

</details>

**Эксперимент 3. Запятая в CSV.** В методе `BuildCsv` уберите `CultureInfo.InvariantCulture` из `ToString`, чтобы осталось `ToString("0.00")`. Посмотрите в файл CSV.

На русском компьютере числа станут через запятую: `2,17` вместо `2.17`. Человек в Excel может и не заметить, а программа, которая читает этот файл, ошибётся.

### ★ События вне смены

Если событие произошло **раньше начала смены или позже её конца**, его нельзя учитывать. Например, отказ в 21:15 дал бы отрицательный простой: конец смены (20:00) раньше отказа. Программа должна пропустить такую строку и написать предупреждение.

Проверьте: добавьте в конец журнала строку `2027-01-20 21:15;EQ-002;ОТКАЗ` и запустите.

<details>
<summary>▶ Подсказка</summary>

В `ProcessLine`, после проверки события, сравните `time` с `ShiftStart` и `ShiftEnd`. Если время вне смены — добавьте предупреждение и выйдите через `return`.

</details>

### ★★ Имя отчёта от пользователя

Пусть программа перед сохранением спрашивает, как назвать файл отчёта.

Но тут есть **опасность**. Пользователь может ввести `../../important`. `..` означает «папка выше», и `Path.Combine` склеит путь **за пределы** папки `reports`. Отчёт может перезаписать чужой важный файл. Это настоящая уязвимость, её называют **обход каталога** (path traversal).

Защитите программу: из того, что ввёл пользователь, оставьте **только имя файла**, без папок.

<details>
<summary>▶ Подсказка</summary>

Метод `Path.GetFileName` возвращает только имя файла: из `"../../important"` получится `"important"`. Проверьте ещё случаи, когда пользователь просто нажал Enter или ввёл `..` — тогда используйте имя по умолчанию.

</details>

## Вопросы для самопроверки

Сначала ответьте сами, потом откройте ответ.

**1. Почему для «кто сломан прямо сейчас» выбран словарь, а не список?**

<details>
<summary>▶ Ответ</summary>

Нам нужно находить станок по коду. В списке пришлось бы перебирать все элементы, а словарь находит значение по ключу сразу.

</details>

**2. Что вернёт `Hours`, а что `TotalHours` для простоя 26 часов 35 минут?**

<details>
<summary>▶ Ответ</summary>

`Hours` — 2, потому что считает часы только в пределах суток. `TotalHours` — 26,58, всё время в часах.

</details>

**3. Что будет, если в `AddDowntime` сразу написать `downtime[code] += duration;` без проверки?**

<details>
<summary>▶ Ответ</summary>

Для станка, которого ещё нет в словаре, программа упадёт с ошибкой `KeyNotFoundException`: прибавлять не к чему.

</details>

**4. Чем отброшенные строки отличаются от предупреждений?**

<details>
<summary>▶ Ответ</summary>

Отброшенную строку невозможно прочитать: битая дата, неверный код, неизвестное событие. Строку с предупреждением прочитать можно, но в ней что-то подозрительное: например, время пошло назад.

</details>

**5. Зачем отчёт собирается в `StringBuilder`, а не сложением строк?**

<details>
<summary>▶ Ответ</summary>

Строки нельзя изменить, и каждое сложение создаёт новую строку, копируя весь текст заново. `StringBuilder` — черновик, куда можно дописывать без копирования.

</details>

**6. Почему EQ-005 после шага 3 не было в результате?**

<details>
<summary>▶ Ответ</summary>

Его так и не починили, строки `ПОЧИНЕН` не было, поэтому простой не посчитался. На шаге 4 метод `CloseShift` досчитал его простой до конца смены.

</details>

## Словарик

| Слово | Что значит |
| --- | --- |
| **Простой** | Время, пока станок сломан и не работает |
| **Журнал** | Файл, куда записываются все события со станками |
| **Ключ** | То, по чему ищут в словаре. У нас — код станка |
| **Значение** | То, что хранится в словаре по ключу |
| **DateTime** | Момент времени: дата и время вместе |
| **TimeSpan** | Промежуток времени: сколько прошло |
| **Формат** | В каком виде записана или выводится дата: `yyyy-MM-dd HH:mm` |
| **StringBuilder** | «Черновик» для сборки длинного текста |
| **CSV** | Таблица, записанная обычным текстом через точку с запятой |
| **Поле** | Переменная, объявленная в классе, а не в методе. Её видят все методы |
| **Автоматизация** | Когда программа делает скучную повторяющуюся работу за человека |
